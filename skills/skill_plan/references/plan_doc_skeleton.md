# 기획 문서 표준 골격 (plan_doc_skeleton)

> skill_plan v2 공통 규약. **모든 상세 문서**(02·04·05·06·07·08·09·10·11·12)는 본 골격을 따른다.
> `INDEX.md`·`01_overview`·`13_followups`는 오케스트레이터 합성 문서로 일부 항목만 적용(§6).

본 문서는 각 plan_* agent가 산출물을 만들 때 참조하는 **문서 형태 계약**이다. 내용(무엇을 쓰는가)은 각 agent가 정하고, 형태(어떤 구조로 쓰는가)는 여기서 강제한다.
> 서술 눈높이(사람용/개발용 문서를 누구 눈높이로 쓰는가)는 §9로 규율한다.

---

## 1. 4단 표준 골격

```
# NN. 제목 (English Subtitle)
> 담당: <agent/role> · 깊이: <light|standard|deep> · <요약 지표 1줄>
> <문서 한 줄 목적>
---
## 0. 개요
## 1. 한눈에 보기
## 2 ~ N. 상세
## (말미) 요약 / 요약 통계
## 문서 메타
```

순서 고정. 섹션 번호는 `## 0.` `## 1.` …로 매기고, 하위는 `### 0-1.` 형식.

---

## 2. 헤더 블록쿼트 (필수 3요소)

```
# 04. 요구사항 명세 (FR / NFR / 제약)

> 담당: plan_requirement_analyzer · 깊이: deep · 총 FR 34 / NFR 25
> 본 문서는 체계·우선순위·표기 규칙(§0) → 한눈에 표(§1) → 상세(§2~) 순으로 구성한다.
```

- 1행: `# NN. 한글제목 (English Subtitle)`
- 2행: `> 담당: <producer> · 깊이: <depth> · <핵심 지표>` — 지표는 그 문서의 대표 수치(요구 수·화면 수·엔티티 수 등).
- 3행: `> <문서 한 줄 목적>`
- 직후 `---` 구분선.

---

## 3. `## 0. 개요`

문서 본문을 읽기 전 **체계를 먼저 선언**한다. 하위 4종(문서 성격에 맞게 취사):

| 하위 | 내용 | 필수 |
|---|---|---|
| `### 0-1. 목적·범위` | 이 문서가 정의하는 것·전제·다른 문서와의 경계 | 필수 |
| `### 0-2. <ID 체계 / 도메인 / 분류 체계>` | 이 문서가 발번/참조하는 ID 규칙 (예: `FR-###`, `FN-{CAT}-##`) → `plan_id_system` 준수 | 필수 |
| `### 0-3. 우선순위 정의` | Must/Should/Could 등 등급 정의 (해당 문서만) | 선택 |
| `### 0-4. 표기 규칙` | AC·측정지표·권한주체 등 본문 약물 설명 | 권장 |

> 원칙: §0를 읽으면 본문의 모든 ID·표기가 자명해져야 한다.

---

## 4. `## 1. 한눈에 보기`

상세 진입 전 **표 2종**으로 전체를 조망:

- `### 1-1. <카테고리/영역 요약표>` — 카테고리별 개수·우선순위 분포·대표 항목 (집계 행 포함).
- `### 1-2. <전체 목록표>` — 모든 항목을 `ID | 제목 | 우선순위 | 카테고리 | 참조` 한 줄씩.

> light depth는 1-2(전체 목록)만으로 축약 가능. standard 이상은 2종 모두.

---

## 5. `## 2 ~ N. 상세`

ID 태그 항목을 카테고리/그룹 단위로 묶어 기술. 항목 표제는 ID를 포함:

```
### [FR-007] 파일 등록 (미분류 허용) — Must      (요구사항)
### [SC-05] 문항 분리 작업 화면 (분할 패널)       (화면)
### [ENT-013] questions                          (엔티티)
### FN-QST-01 ...                                 (기능)
```

- 항목 본문은 agent별 고유 양식(AC·구성요소·컬럼 등)을 따른다.
- **다른 문서의 ID를 인용할 때는 발번하지 말고 참조만** 한다(`plan_id_system` 레지스트리 규칙).
  - 참조는 **정의된 의존 DAG 엣지에 한하며**(스파게티 cross-link 금지), 파생물(src/runbook/코드)은 **역참조하지 않는다** — `plan_ssot_integrity` 준수.
- 다이어그램은 `rules/rule_visualization_guide.md` 준수:
  - 기본 **ASCII 코드블록**(트리·박스·흐름·와이어프레임).
  - mermaid는 `sequenceDiagram`·ERD(`erDiagram`) 등 ASCII가 비효율적인 경우만.
  - ASCII 박스 내부는 ASCII 문자만(한글은 박스 밖 캡션).

## 6. 말미 — 요약 / 문서 메타

- `## (말미) 요약` 또는 `요약 통계`: 총계·분포·커버리지 확인을 표/개조식으로.
- `## 문서 메타` (권장, 합성 문서·신규 문서는 필수):
  ```
  ## 문서 메타
  - 버전 / 생성·갱신 일자   ← 리비전 정보는 여기까지만. 본문 changelog·diff 삽입 금지(`plan_ssot_integrity §3`)
  - 관련 문서: DAG 엣지에 해당하는 문서만 상호 링크 예) [`04_requirements`](./04_requirements.md) (`plan_ssot_integrity §2`)
  - 미해결·후속: 13_followups로 이관할 항목
  ```

## 7. depth 스케일 (모든 agent 공통)

| depth | §0 | §1 | 상세 | 요약 | 문서메타 |
|---|---|---|---|---|---|
| light | 0-1만 | 1-2만 | 핵심 항목, AC 생략 | 총계만 | 생략 가능 |
| standard | 0-1·0-2(·0-3) | 1-1·1-2 | 전 항목, 핵심만 상세 | 분포 | 권장 |
| deep | 0-1~0-4 | 1-1·1-2 | 전 항목 풀 상세 + 근거 | 커버리지 검증 | 필수 |

## 9. 언어 눈높이 (사람용 / 개발용 문서)

문서를 두 부류로 나눈다. 뼈대·형식·식별자는 §1~§6대로 공통 유지하되, **서술 눈높이**만 부류에 따라 달리한다.

**사람용 문서 (01·02·03·04·06)** — 개발을 모르는 사람도 읽을 수 있게 쓴다.
- 뼈대·번호·꼬리표(FR/NFR/카테고리/MoSCoW/AC 등)는 그대로 유지한다.
- 문장·설명·제목 풀이는 전문용어를 남발하지 않고, 무엇을 만들고 싶은지 직관적으로 전달한다.
- 어쩔 수 없이 어려운 말을 쓰면 옆에 쉬운 풀이를 붙인다.
- 04는 사람과 가장 가까운 문서 — 이 원칙을 가장 강하게 적용한다.
- 쉽게 ≠ 대충: 각 항목은 뒷 문서(FN/SC/ENT)로 이어질 만큼 구체적이어야 한다.

**개발용 문서 (05·07·08·09·10·11·12)** — 개발자와 논의하는 전문용어·정밀 명세를 그대로 쓴다.
