# Prompt 작성 문체 정책

> prompt 메타 파일은 LLM이 읽고 실행한다. "왜(Why)"는 문장식으로 짧게, "무엇/어떻게(What/How)"는 개조식으로 명시한다.

## 1. 섹션별 권장 스타일 매핑

| 섹션 / 위치 | 권장 스타일 | 근거 |
|---|---|---|
| frontmatter `description` | 문장식 1줄 | 자연어 트리거 매칭 |
| `# Goal` / `# Role` / `# Prblm` | 문장식 1~2줄 (`>` 인용 블록 허용) | 의도·역할 전달 |
| `# Variables` 정의 | 개조식 | 타입·필수·기본값 명시 |
| `# References` 매핑 | 개조식 | 변수=경로 매핑 |
| `## Step N` 헤더 직후 1줄 | 문장식 (선택) | 해당 Step 의도 요약 |
| `## Step N` 본문 | 개조식 (중첩 bullet) | 순서·체크리스트성 |
| `# Rules` / `## Rules` | 개조식 | 분기·제약 명시 |
| `# Error Handling` | 개조식 (`조건 → 액션`) | 분기 명확화 |
| `# Output` | 개조식 + 코드블록 예시 | 산출물 명세 |
| `## 예외` | 개조식 | 우선순위 명시 |
| 표(Table) | 적극 권장 | 비교·매핑·분류에 최적 |

## 2. 작성 디테일 규칙

### 2-1. bullet 구성
- 한 bullet 안에 문장 1개 원칙
- 문장이 2개 이상 필요하면 하위 bullet으로 분리
- bullet은 핵심 → 부연 순으로 중첩

### 2-2. 종결어미
- 개조식: 명사형(`확인`, `수행`, `반환`) 또는 동사형(`확인한다`, `수행할 것`) 중 하나로 한 파일 내 통일
- 종결어미 혼용 금지
- 문장식: 평서형(`~한다`) 사용, 존댓말 금지

### 2-3. 조사·연결어
- 의미 전달에 불필요한 조사 생략
- "또한", "그리고", "따라서" 등 연결어는 개조식에서 생략, bullet 분리로 표현

### 2-4. 강조
- **굵게**: 핵심 키워드, 분기 조건
- `inline code`: 변수명·파일 경로·명령
- `>` 인용: 도입 문장식 (선택)

## 3. 안티패턴 (금지)

- 한 bullet에 3문장 이상 나열
- "~합니다", "~해야 합니다" 존댓말
- 동일 정보를 문장식·개조식으로 중복 기재
- 의미 없는 도입어 ("이 섹션에서는…", "여기서는…")
- bullet 안에 평문 문단 끼워넣기

## 4. 적용 예시 — Before / After

### Before (문장식 과다)
```markdown
## Step 1. 데이터 분석
이 단계에서는 입력된 데이터를 분석하여 구조와 분포를 파악합니다.
먼저 데이터를 로드하고, 그 다음 결측값을 확인하며, 마지막으로 시각화를 수행합니다.
이 과정에서 발견된 이상치는 별도로 기록되어야 합니다.
```

### After (하이브리드)
```markdown
## Step 1. 데이터 분석
> 입력 데이터의 구조·분포·품질을 파악한다.

- 데이터 로드
- 결측값 확인
- 시각화 수행
- 이상치 발견 시 별도 기록
```

## 5. 적용 우선순위

| 우선순위 | 출처 | 비고 |
|---|---|---|
| 1 | SKILL.md / AGENT.md / RULE.md 내 별도 문체 정책 | 개별 명시가 최우선 |
| 2 | 본 prompt_style.md | skill_prompt_manager 작업 시 자동 적용 |
| 3 | 기존 파일의 현행 스타일 (UPDATE 모드) | 하위호환 — 부분 수정 시 주변 스타일 따름 |

## 6. 예외

- 외부 문서·원문 인용은 원형 보존
- 사용자 응답·예시 코드·예시 출력은 본 정책 미적용
- 본 정책은 메타 prompt 파일에 한정. 사용자 산출물(노트/리포트)은 해당 SKILL의 스타일을 따름
